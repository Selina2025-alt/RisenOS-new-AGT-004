# 不能仅靠 GitHub 补齐部分的实施计划

开源组件已经用于工程能力，但以下项目依赖宿主权限、RISEN 家族协议或企业治理
数据，不能通过安装仓库直接完成。

## 阶段 A：宿主模型闭环（P0，部署方待实施，1–2 周）

参与方：Codex/JovaAI 平台团队、AGT-RSN-004。

实施：

1. Codex 和 JovaAI 分别实现 `HostRuntimeExecutor`；
2. 支持结构化 JSON、超时、取消、幂等、流量配额和错误分类；
3. 返回宿主 ID、模型版本、提示词版本、Token、耗时等审计元数据；
4. 图片能力作为可选 Capability 单独声明；
5. 使用 Promptfoo 黄金样本分别跑 Codex/JovaAI 回归。

验收：Schema 合规率 100%，宿主失败不产生内容版本，不保存任何供应商密钥。

## 阶段 B：RISEN 家族协作闭环（协议代码已完成，联调待实施，1–2 周）

参与方：AGT-RSN-003、004、005、006。

本仓库已完成：

1. 定义带版本的 EvidenceRequest/EvidenceFulfillment 契约；
2. 定义 ReviewRequest、段落/Claim 批注和 ReviewDecision 契约；
3. 定义 ContentPackage/HandoffReceipt 契约；
4. 使用 Outbox、签名、幂等键和重放保护；
5. 建立本地契约测试、失败重试、死信和租约恢复。

联调剩余：003/005/006 提供实际端点、共享密钥管理、契约测试环境和故障演练。

验收：003 补证据后可继续原 Run；006 意见精确定位版本和 Claim；005 只确认收到
内容包，不返回发布或效果数据。

## 阶段 C：企业内容治理（P0，2–4 周）

参与方：品牌、法务、合规、信息安全、内容团队。

实施：

1. 将真实 BrandRule、禁用表达、强制披露、版权范围和高风险矩阵整理为版本化规则；
2. 规则代码进入 OPA，业务词表和审批矩阵进入受控数据源；
3. 每条规则配置责任人、生效期、例外审批和测试样本；
4. 规则变更经过双人审批并触发内容黄金集回归。

验收：阻断规则无法绕过；规则版本可追溯；PublicStatement 等高风险内容强制人工审核。

## 阶段 D：中文 PII 与附件安全（基础门已完成，企业增强 2–3 周）

已完成：Secret/邮箱/手机号/身份证/银行卡/Prompt Injection 本地识别，模型输入脱敏，
附件大小/MIME/checksum/病毒扫描/提取契约，图片解码限制和元数据清理。

企业增强：

1. 需要更高召回率时内网部署 Presidio，不把内容发送到外部服务；
2. 增加统一社会信用代码、地址和企业自定义实体识别器；
3. 建立中文误报/漏报集，并定义“阻断、脱敏、提醒”三级处置；
4. 由宿主在隔离容器中落地真实附件解析和病毒扫描；
5. PII 结果进入 `ContentValidationResult`，不做发布后监测。

验收：关键实体召回率和误报率达到企业安全标准；Presidio 不可用时高风险任务
fail-closed。

## 阶段 E：生产身份与数据可靠性（应用层已完成，基础设施 2–3 周）

应用层已具备签名身份校验、RBAC、组织查询边界、审计、死信、排队任务取消、
OpenTelemetry 和就绪探针。部署方仍需：

1. 用企业 SSO/OIDC 网关签发身份头并隔离 API；
2. 完成组织、角色、内容资产和审计日志的独立越权测试；
3. PostgreSQL PITR、Redis HA、对象存储版本和跨区备份；
4. 完成恢复演练、死信重放、运行中任务人工接管；
5. 配置 OpenTelemetry 告警和运维 SLO。

验收：跨组织泄漏为 0；恢复演练达到约定 RPO/RTO；每个交付包可用 traceId 重建。

## 阶段 F：Skill 供应链（代码型 Skill 启用前，1–2 周）

1. 当前仅允许声明式内容 Skill；
2. 若未来开放代码型 Skill，再接入 Semgrep、SBOM、签名和沙箱；
3. Skill 来源、依赖、权限、测试、审批和撤销均需可审计；
4. 激活前运行安全扫描、内容黄金样本和边界检查。

验收：未经签名、扫描、回归和人工批准的 Skill 不能进入生产。

## Temporal 决策门

先由 JovaAI 确认是否已经提供耐久任务、重放、定时器、取消和补偿。如果已提供，
AGT-RSN-004 只实现 RuntimePort Adapter；只有缺少这些能力时才引入 Temporal，
避免两套工作流状态机并存。
