# 第四篇 全球 100+ AI Agent 平台竞争格局研究

<!-- P01550; style=Heading 2 -->
## 第 17 章 全球 AI Agent 平台 12 大分类方法

<!-- P01551; style=Normal -->
全球 AI Agent 平台正在快速爆发。

<!-- P01552; style=Normal -->
如果只从表面看，今天几乎所有 AI 公司、云计算公司、企业软件公司、自动化公司、开发者工具公司、数据平台公司、搜索公司、代码工具公司，都在讲 AI Agent。它们都在强调智能体、自动化、工具调用、企业知识连接、多智能体协作、Agent Studio、Agent Runtime、Agent Marketplace、MCP、RAG、Workflow、Agentic Automation。

<!-- P01553; style=Normal -->
但如果进一步拆解，就会发现这些平台所处的位置并不相同。

<!-- P01554; style=Normal -->
有的平台强在模型能力。
有的平台强在企业应用生态。
有的平台强在 Agent 构建。
有的平台强在 Workflow 编排。
有的平台强在多智能体开发框架。
有的平台强在知识库和 RAG。
有的平台强在流程智能。
有的平台强在 RPA 自动化。
有的平台强在销售、客服、营销等垂直场景。
有的平台强在软件工程智能体。
有的平台强在个人搜索和研究。
有的平台开始接近企业级或生态级平台。

<!-- P01555; style=Normal -->
因此，要研究全球 100+ AI Agent 平台，不能简单按照公司知名度罗列，也不能只按照“有没有 Agent”来分类，而必须按照平台在 AI Agent 能力链条中的位置进行分层。

<!-- P01556; style=Normal -->
本报告将全球 AI Agent 平台划分为 12 大类型：

<!-- P01557; style=Normal -->
第一类，基础模型与通用智能体平台。
这一类平台以大模型、通用智能、工具调用、多模态、推理、浏览器操作、代码能力和通用任务执行为核心。它们代表 AI Agent 的底层智能能力。

<!-- P01558; style=Normal -->
第二类，企业智能体平台。
这一类平台以企业内部 Agent 构建、企业知识连接、企业应用集成、权限治理、安全管理和组织级部署为核心。它们代表 AI Agent 进入企业生产环境的关键方向。

<!-- P01559; style=Normal -->
第三类，Agent Builder / Agent Studio 平台。
这一类平台主要帮助开发者或企业搭建、配置、部署和监控智能体。它们解决的是“如何创建 Agent”的问题。

<!-- P01560; style=Normal -->
第四类，Workflow / iPaaS / 自动化平台。
这一类平台以系统连接、流程编排、API 调用、企业应用集成和自动化任务流转为核心。它们解决的是“如何让 AI 嵌入流程”的问题。

<!-- P01561; style=Normal -->
第五类，多智能体开发框架。
这一类平台以多个智能体之间的分工、通信、协作、调度和复杂任务执行为核心。它们解决的是“多个 Agent 如何协作”的问题。

<!-- P01562; style=Normal -->
第六类，RAG / 知识工程 / 数据智能平台。
这一类平台以企业知识库、向量数据库、检索增强生成、数据治理、知识抽取、上下文工程和企业搜索为核心。它们解决的是“Agent 如何获得知识和上下文”的问题。

<!-- P01563; style=Normal -->
第七类，流程智能与运营智能平台。
这一类平台以流程挖掘、流程智能、运营数字孪生、业务流程优化和运营上下文为核心。它们解决的是“Agent 如何理解企业内部运营”的问题。

<!-- P01564; style=Normal -->
第八类，RPA 与 Agentic Automation 平台。
这一类平台以机器人流程自动化、桌面自动化、企业应用自动化、流程执行和人机协同为核心。它们解决的是“Agent 如何与机器人和流程自动化结合”的问题。

<!-- P01565; style=Normal -->
第九类，CRM / 销售 / 营销 / 客服智能体。
这一类平台聚焦客户关系、销售增长、营销内容、客户服务、客户成功和商业沟通场景。它们解决的是“Agent 如何进入业务前台”的问题。

<!-- P01566; style=Normal -->
第十类，编程智能体与软件工程平台。
这一类平台以代码生成、代码审查、Bug 修复、Pull Request、测试、部署和软件工程自动化为核心。它们解决的是“Agent 如何参与软件生产”的问题。

<!-- P01567; style=Normal -->
第十一类，搜索、浏览器、研究与个人生产力智能体。
这一类平台以搜索、研究、浏览器操作、会议纪要、笔记、个人知识管理和个人任务管理为核心。它们解决的是“Agent 如何提升个人信息处理效率”的问题。

<!-- P01568; style=Normal -->
第十二类，产业级、生态级、网络级平台。
这一类平台已经超越单点工具，开始触及企业数据、企业运营、流程智能、企业应用生态、自动化生态、云基础设施或产业网络。它们是 JovaAI 最需要重点对标的参照对象。

<!-- P01569; style=Normal -->
这 12 大类型共同构成了全球 AI Agent 平台的完整版图。

<!-- P01570; style=Normal -->
但需要强调的是，这 12 类平台并不是同一个层级。

<!-- P01571; style=Normal -->
基础模型平台提供底层智能。
Agent Builder 提供构建工具。
Workflow 平台提供流程连接。
RAG 平台提供知识上下文。
多智能体框架提供协作机制。
企业智能体平台提供组织级治理。
流程智能平台提供运营上下文。
RPA 平台提供执行自动化。
垂直业务智能体提供场景落地。
个人生产力智能体提供交互入口。
生态级平台提供企业级扩展能力。
产业级 Agentic OS 则要把智能体、企业、产业交易和上下游资源连接成网络。

<!-- P01572; style=Normal -->
这也意味着，全球 AI Agent 平台看似繁荣，但大多数平台只解决 Agent 能力链条中的一部分。

<!-- P01573; style=Normal -->
很多平台解决“模型能不能思考”。
很多平台解决“Agent 能不能调用工具”。
很多平台解决“企业能不能搭建 Agent”。
很多平台解决“流程能不能自动化”。
很多平台解决“多个 Agent 能不能协作”。
很多平台解决“Agent 能不能连接知识库”。
很多平台解决“企业内部能不能治理 Agent”。

<!-- P01574; style=Normal -->
但真正的产业级 Agentic OS 要解决的是：

<!-- P01575; style=Normal -->
智能体能否理解产业？
智能体能否建模交易？
智能体能否代表企业？
智能体能否跨企业协同？
智能体能否连接上下游资源？
智能体能否组织产业服务生态？
智能体能否在真实产业交易中持续进化？

<!-- P01576; style=Normal -->
这正是 JovaAI 与全球多数平台的根本区别。

<!-- P01577; style=Normal -->
因此，本篇的研究并不是为了证明全球平台不重要，而是为了说明：全球平台共同推动了 AI Agent 时代的到来，但它们大多数仍然停留在模型、工具、流程、企业内部、开发框架或连接器层面。JovaAI 的独特价值，在于它进一步进入产业 Know-how、跨产业实时交易算法、产业级独立站、多企业智能体协同和自进化网络层。

<!-- P01578; style=Normal -->
一句话概括：

<!-- P01579; style=Normal -->
全球 AI Agent 平台正在共同证明 Agent 是大方向；而 JovaAI 要证明的是，AItoB 的真正终局不是普通 Agent，而是产业级 Agentic OS。
