# 第 19 章 企业智能体平台研究

> 来源：01_《JovaAI 艾氪智能全球领先性研究报告：从企业智能体到产业级 Agentic OS 的代际跃迁》.docx；定位：P01613–P01645。

<!-- P01613; style=Heading 2 -->
## 第 19 章 企业智能体平台研究

<!-- P01614; style=Normal -->
企业智能体平台，是全球 AI Agent 竞争中最重要的一类。

<!-- P01615; style=Normal -->
如果说基础模型平台代表底层智能能力，那么企业智能体平台代表 AI Agent 进入组织生产环境的关键阶段。它们的出现说明，AI Agent 已经不再只是个人助手或开发者实验，而开始成为企业内部员工、客户服务、销售、IT、HR、财务、运营和管理流程中的新型工作单元。

<!-- P01616; style=Normal -->
这一类代表平台包括 Salesforce Agentforce、Microsoft Agent 365、Microsoft Copilot Studio、Google Gemini Enterprise Agent Platform、ServiceNow AI Agents、Oracle AI Agent Studio、SAP Joule、Workday Illuminate、IBM watsonx Orchestrate、Adobe AI Agents、Atlassian Rovo、Box AI、Dropbox Dash、Slack AI、Zoom AI Companion、Kore.ai、Moveworks 等。

<!-- P01617; style=Normal -->
企业智能体平台的核心价值，是把 Agent 从“个人可用”推进到“企业可部署”。

<!-- P01618; style=Normal -->
企业与个人不同。个人使用 AI，可以容忍一定程度的不稳定、不完整和试错。但企业使用 AI，必须考虑安全、权限、合规、审计、数据边界、组织流程、责任链条、系统集成和业务结果。

<!-- P01619; style=Normal -->
因此，企业智能体平台通常重点解决六类问题。

<!-- P01620; style=Normal -->
第一，企业智能体构建。
企业可以创建不同角色的智能体，例如销售智能体、客服智能体、IT 智能体、HR 智能体、财务智能体、营销智能体、运营智能体等。

<!-- P01621; style=Normal -->
第二，企业知识连接。
智能体可以连接企业内部文档、知识库、客户记录、产品资料、流程规范、历史工单、会议记录、业务数据等。

<!-- P01622; style=Normal -->
第三，企业应用集成。
智能体可以连接 CRM、ERP、ITSM、协同办公、数据平台、工单系统、财务系统、HR 系统、客服系统等企业应用。

<!-- P01623; style=Normal -->
第四，权限与安全治理。
企业可以定义智能体访问哪些数据、调用哪些系统、执行哪些任务、是否需要审批、如何记录日志、如何进行审计。

<!-- P01624; style=Normal -->
第五，组织级管理。
企业可以管理智能体生命周期，包括创建、发布、监控、优化、停用、升级和合规检查。

<!-- P01625; style=Normal -->
第六，平台生态扩展。
大型企业软件平台通常会把智能体能力与自身生态绑定，形成面向客户、员工、开发者和合作伙伴的 Agent 体系。

<!-- P01626; style=Normal -->
这一类平台的成熟，代表全球企业软件正在进入 Agent 化阶段。

<!-- P01627; style=Normal -->
Salesforce 的 Agentforce 说明 CRM、销售、客服和客户关系场景正在被自主智能体重构。Microsoft Agent 365 说明企业需要管理整个组织中的 Agent fleet，需要统一观察、治理和安全控制。Google Gemini Enterprise Agent Platform 说明云厂商正在把 Agent 构建、扩展、治理和优化变成企业 AI 平台能力。Oracle、SAP、ServiceNow、Workday 等平台也说明，ERP、ITSM、HR、财务和业务流程都在进入智能体时代。

<!-- P01628; style=Normal -->
但是，这一类平台依然有明显边界。

<!-- P01629; style=Normal -->
第一，它们多数围绕自有生态展开。

<!-- P01630; style=Normal -->
企业智能体平台通常依托自身已有的云、SaaS、CRM、ERP、ITSM、办公或企业应用生态。它们在自有生态内能力很强，但跨企业、跨行业、跨平台的产业协同不是其天然主战场。

<!-- P01631; style=Normal -->
第二，它们主要服务企业内部流程。

<!-- P01632; style=Normal -->
企业智能体平台的典型场景包括客服自动化、销售跟进、员工服务、IT 工单、HR 咨询、财务分析、运营报告、办公协同。这些都很重要，但它们主要提升单企业内部效率或客户触点效率，尚未真正进入多企业产业交易网络。

<!-- P01633; style=Normal -->
第三，它们不一定具备深层产业交易建模能力。

<!-- P01634; style=Normal -->
企业智能体可以调用 CRM，也可以调用 ERP，还可以回答业务问题。但真实 ToB 产业交易涉及供应商、客户、渠道、物流、金融、服务商之间的多方关系，涉及账期、赊销、返点、返利、动态价格、区域政策、库存协同和交付服务。企业智能体平台通常不把跨产业实时交易算法作为核心底座。

<!-- P01635; style=Normal -->
第四，它们不一定解决企业独立入口问题。

<!-- P01636; style=Normal -->
很多企业智能体平台让企业在某个中心化生态中创建和使用智能体。企业获得了平台能力，但也可能成为平台生态中的一个账号。AItoB 时代，企业不仅要使用智能体，还要拥有自己的智能体门户、数据阵地、客户入口、供应商入口和产业协同节点。

<!-- P01637; style=Normal -->
第五，它们不天然形成上下游裂变网络。

<!-- P01638; style=Normal -->
企业智能体平台通常服务企业本身，而不是通过一家企业自然裂变连接其上下游生态。产业级网络效应需要不同企业节点之间形成持续协同，而不是只在单企业内部优化流程。

<!-- P01639; style=Normal -->
因此，本报告对企业智能体平台的判断是：

<!-- P01640; style=Normal -->
企业智能体平台代表第三代智能体的重要成熟。
它们解决了企业内部 Agent 平台化问题。
但它们尚未完全解决跨企业产业级智能体网络问题。

<!-- P01641; style=Normal -->
JovaAI 与这一类平台的差异，恰恰在于 JovaAI 不是只把 Agent 放进企业内部，而是让企业拥有自己的智能体团队，并通过独立站和 Wtree 世界树进入产业智能体网络。

<!-- P01642; style=Normal -->
企业智能体平台让企业内部更智能。
JovaAI 让企业与外部资源的连接方式更智能。

<!-- P01643; style=Normal -->
企业智能体平台让员工和客户可以被 Agent 服务。
JovaAI 让供应商、客户、渠道、物流、金融、服务商之间能够通过智能体协同。

<!-- P01644; style=Normal -->
企业智能体平台强调企业内部治理。
JovaAI 强调多企业身份、权限、交易和产业网络治理。

<!-- P01645; style=Normal -->
这就是 JovaAI 与全球企业智能体平台之间的代际差异。
