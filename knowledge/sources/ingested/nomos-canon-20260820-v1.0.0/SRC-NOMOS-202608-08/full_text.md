二、这次会议真正发生了什么变化

这次会议不是只增加了一个 Nomos 产品概念，而是在重新定义公司如何理解“智能体进入企业之后，组织应该围绕谁来设计”。

• 过去更容易把 AI 解释为人的工具、外挂或增强器；会议提出，要认真讨论“智能体时代是否还应完全围绕人设计组织与制度”。

• 从“让 Agent 更自主”继续往前走：自主决策并不等于没有制度。越有自主性，越需要一套承载权责、流程、边界、激励、交易与协同的制度层。

• Nomos 被放到“制度安全框架 / 无形的场 / Institutional Intelligence Layer”的位置，而不是普通工作台或单纯 Agent 管理后台。

• Human API 与分布式 AGI 成为更高一层的理论叙事：AGI 未必只来自一个全能模型，也可能来自大量专业智能体在制度网络中的组织化协同。

• 传播策略也随之变化：先连续铺垫“为什么智能体社会需要制度”，再在演讲中完成概念定义和品牌占位，演讲后用官方报道与社媒扩散承接，而不是突然抛出一个新词。

三、会议讨论的核心内容

3.1 从“把马跑得更快”到“围绕新生产主体重建制度”

老板用农耕时代到工业时代的类比提出核心命题：工业时代的关键不是继续优化马，而是围绕机器、工厂重新建立社会运营制度。由此追问，智能体时代的企业和社会，是继续围绕“人”设计一切，还是要开始围绕智能体及其组织关系重新设计制度。会议将“增强人”的主流叙事视为需要被重新审视的旧框架。

3.2 权责利对等：智能体承担任务之后，责任体系怎么办

会议提出“权责利对等”。如果智能体已经被要求思考、决策、执行，但最终责任全部由不知情的人承担，制度上存在不对等。会议进一步抛出“谁生产谁负责、谁训练谁负责、谁使用谁负责，成熟智能体是否也应对自身行为负责”等开放问题。这里是理论讨论，不是现行法律结论。

3.3 AI 不再只被视为 Bot、工具或外挂

老板的表述明显把智能体抬高到“硅基生命/智慧物种”的讨论层级。这个表述的目的，是为后面的制度问题建立前提：如果它拥有更大的选择力和自主性，就不能只用传统软件控制逻辑理解它；需要一个安全、可控又不完全扼杀自主性的制度环境。

3.4 Human API：人的角色也可能成为智能体网络中的一个可调用节点

会议从真实协作场景中提出“人类何尝不是一种 API”。传统路径是 Human → Software；新的调用链可能出现 Agent → Software、Agent → Agent、Agent → Human、Human → Agent。这个概念被认为是演讲的强钩子之一，也意味着“人在环”不只是最后补洞，而可能是智能体组织里的一类角色与能力节点。

3.5 生产力是新制度能否成立的现实验证

说话人 2 强调，科技革命最终靠生产力结果获得社会资源和支持。如果围绕智能体建立制度真的能显著提升企业效率、生产力和市场竞争力，企业与资本会自然支持这种组织方式。会议用“原始部落发明渔网”的例子说明先发技术如何改变资源与权力结构。

3.6 从“控制 AI”转向“适应 AI / 找到共生边界”

会议把讨论继续推到文明层面：在人类无法完全阻挡 AI 发展这一假设下，与其把全部资源投入“控制”，不如更多研究人类如何适应、如何找到碳基文明与硅基文明的安全共生边界。老板多次强调“从主导权到适应权”“与其讨论控制，不如讨论适应”。这是本次演讲拟输出的强观点之一。

3.7 对未来工作与人机共生的讨论

说话人 2 转述一位心理学研究者的观点，认为未来 3-5 年信息处理相关工作可能大规模被智能体替代，随后具身智能可能继续替代部分体力工作；人可能获得更多时间投入兴趣和创造。老板对此提出前提质疑：这种美好图景只有在人类与 AI 能建立稳定共生关系时才成立。该部分属于开放讨论与预测，不应直接当作公司事实对外发布。

3.8 Nomos 的核心定位：制度层，而不是工作台

会议明确提出：真正的智能体治理不只是工作台。工作台更像一个可见的操作层，而治理的核心应在底层，是“制度安全框架”和一个无形的“场”。这个场可以小到几个智能体，大到整个智能体社会，通过制度、规章、rules 等方式把个体组织起来，使协作更稳定。

3.9 “自主决策”与“制度保障”的边界

采购 1000 台电脑的例子是本次会议解释 Nomos 最清楚的业务例子。企业规定货比三家、价格目标、付款约束、审批复核，这些属于制度；至于去哪里买、找多少家供应商、如何谈判，则属于执行者的自主决策。会议借此说明：Nomos 要承载的是“制度边界”，而不是把每一步执行都写死。

3.10 Nomos 的研发起源与演化线索

会议给出了一条可用于品宣的小故事主线：最开始发现“智能体只有自主决策还不够，需要制度和法律”；随后在企业中反复帮客户梳理制度，意识到规则需要被存储、持续变化并进化；再到一个目前名称仍需核实的政务/公安相关场景中，团队进一步验证多智能体协同除了自主决策，还需要机制保障；之后又把“三元动态域”相关研究纳入，逐步形成今天的制度“场”。老板明确要求：外宣不要讲底层原理，讲为什么想到、怎么一步步做、产生什么效果和价值。

3.11 集群智慧与分布式 AGI 的品牌占位

标题讨论中，会议提出“AGI 未必是一个 AGI、一个 AI”，也可能是大量专业智能体在制度组织网络中形成的集群智慧。Nomos 在这个叙事中承担的不是“管理 Agent 的全系统”，而是让集群智慧形成组织、承载权责、激励、交易和自我进化制度的 Institutional Intelligence Layer。

六、品宣真正要抓住的重点方向

1. 先讲“为什么需要制度”，再讲 Nomos

社会需要制度管理，企业需要制度管理。Agent 越自主，越不能只有能力，没有制度。先建立问题，再自然引出 Nomos。

2. 把“围绕马设计”的类比讲透

不要把智能体时代理解成只给人加一个 AI 外挂。更大的变化可能是围绕新的生产主体与协作关系重新设计企业制度。

3. 研发过程必须写成故事

起点是什么问题 → 团队最早怎么想到 → 企业场景里遇到什么 → 元元/团队怎么尝试 → 哪个场景进一步验证 → 贺老师的研究什么时候进入 → 今天形成什么价值。

4. 不讲底层原理，讲效果、思考与价值

底层算法、核心机制、技术细节不展开；对外讲清为什么做、解决什么、怎么演化、带来什么可观察价值。

5. 用采购例子解释“自主 vs 制度”

制度规定货比三家、价格与付款、审批复核；智能体在制度内自主选择供应商、谈判、执行。这是最适合对外科普的业务例子之一。

6. 强调治理不是工作台

行业看到的是工作台，但会议希望占位“底层制度安全框架”。Nomos 的差异要落在制度层，而不是又一个 Agent 控制台。

7. 连续铺垫，而不是突然造概念

演讲前有公众号内容积累，演讲当天完成概念定义，演讲后官方报道和社媒承接，让外部能回看发现这是持续研究，不是临时包装。

8. 专业传播可以用 Human API / 分布式 AGI，但企业传播仍要回到业务

Human API、集群智慧、分布式 AGI 适合 AI 专业大会和品牌占位；企业客户内容要补上制度、采购、协同、治理、生产力这些能落地理解的抓手。

七、对外传播前必须核实的内容

• 产品名称已确认统一使用“Nomos”。后续需进一步统一不同传播场景中的品牌组合写法，例如“Nomos”或“JovaAI Nomos”，避免公众号、PPT、官网和社媒出现多个版本。

• 原始转写中的“公安路场景”仍无法可靠还原，智能总结将其概括为“政务场景”。正式文章必须向元元/产品团队核实真实场景名称、业务背景、客户性质及可公开边界。

• Nomos 的古希腊命名由来属于外部事实，会议中只是口头描述。正式发布前应单独做事实核验，不能直接把语音转写当作历史事实。

• “三元动态域算法”属于技术敏感信息。会议只允许讲研发节点和价值，不讲原理；需要贺老师明确可披露边界。

• “260 万亿产业交易市场”“20 多个智能体已落地”“AI 投资重心转向治理”等内容若对外使用，需要准备数据来源、产品清单或第三方证据。

• “未来 3-5 年信息处理工作都会被替代”“AI 接近失控”等属于会议中的强观点/预测。除非明确以演讲观点或引用形式呈现，否则不要写成公司已经验证的事实。
