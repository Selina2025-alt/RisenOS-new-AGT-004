# 30.4 POC 必须有一条“黄金演示链路”

> 来源：01_艾氪智能产业级 Agentic OS 战略与壁垒手册V8.0.docx；定位：P03217–P03238。

<!-- P03217; style=Normal -->
### 30.3 POC 设计不能从功能开始，而要从业务链路开始

<!-- P03218; style=Normal -->
传统软件 POC 经常从功能开始：给客户演几个页面、几个按钮、几个流程。

<!-- P03219; style=Normal -->
JovaAI POC 必须从业务链路开始。

<!-- P03220; style=Normal -->
比如关务 POC，不应该说“我们能做文件解析、规则检索、报告生成”。而应该从客户真实链路开始：

<!-- P03221; style=Normal -->
客户有一款产品要出海；
产品由多个零部件构成；
零部件信息散落在 BOM、SAP、文档里；
关务需要判断 HS Code、原产地、税率和合规风险；
现在靠人工查资料、整理文档、判断风险；
JovaAI 如何把这些步骤交给关务智能体团队完成。

<!-- P03222; style=Normal -->
客户看到的不是功能，而是业务被 AI 接住了。

<!-- P03223; style=Normal -->
报价 POC 也一样。

<!-- P03224; style=Normal -->
不要先演“生成报价单”，而要从客户询价开始：

<!-- P03225; style=Normal -->
客户发来需求；
系统解析商品和规格；
识别客户等级和历史成交；
调用库存和价格规则；
判断合同价、账期、毛利和审批；
生成报价方案；
触发审批；
报价后进入跟进。

<!-- P03226; style=Normal -->
这才是 POC。

<!-- P03227; style=Normal -->
### 30.4 POC 必须有一条“黄金演示链路”

<!-- P03228; style=Normal -->
每个 POC 都必须设计一条黄金演示链路。

<!-- P03229; style=Normal -->
所谓黄金演示链路，是客户看完后最容易被打动、最能体现 JovaAI 价值、最能证明业务闭环的一条路径。

<!-- P03230; style=Normal -->
雅迪关务的黄金链路是：

<!-- P03231; style=Normal -->
产品资料 / BOM 输入 → 零部件拆解 → HS Code / 税则匹配 → 合规资料判断 → 风险提示 → 人工确认 → 报告输出。

<!-- P03232; style=Normal -->
报价智能体的黄金链路是：

<!-- P03233; style=Normal -->
客户询价 → 商品规格识别 → 客户等级和历史成交 → 价格和库存判断 → 毛利校验 → 审批触发 → 报价方案输出。

<!-- P03234; style=Normal -->
展会 AI 交易平台的黄金链路是：

<!-- P03235; style=Normal -->
买家需求 → 展品 / 展商匹配 → 名片交换 / 聊天翻译 → 询盘生成 → 报价跟进 → 展后商机管理。

<!-- P03236; style=Normal -->
采购智能体的黄金链路是：

<!-- P03237; style=Normal -->
采购需求 → 供应商筛选 → 批量询价 → 报价回收 → 比价分析 → 供应商评分 → 采购建议。

<!-- P03238; style=Normal -->
黄金链路不求覆盖全部功能，但必须打中客户最痛的地方。
