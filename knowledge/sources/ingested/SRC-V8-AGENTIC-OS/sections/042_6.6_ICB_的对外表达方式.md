# 6.6 ICB 的对外表达方式

> 来源：01_艾氪智能产业级 Agentic OS 战略与壁垒手册V8.0.docx；定位：P00986–P01006。

<!-- P00986; style=Normal -->
### 6.5 ICB 与 6000+ Skills / CLI 工具集群的关系

<!-- P00987; style=Normal -->
ICB 和 Skills / CLI 工具集群必须一起讲，不能割裂。

<!-- P00988; style=Normal -->
ICB 是产业交易语法。
Skills / CLI 是产业动作工具。
JovaAI OS 是智能体运行秩序。
JovaClaw 是智能体执行层。

<!-- P00989; style=Normal -->
如果只有 ICB 没有工具，智能体懂交易但做不了事。
如果只有工具没有 ICB，智能体能调用工具但不懂何时、为何、以什么权限调用。
如果只有 OS 没有 ICB 和工具，OS 只是运行空间，不是产业操作系统。

<!-- P00990; style=Normal -->
所以，ICB 和工具集群的关系可以这样理解：

<!-- P00991; style=Normal -->
ICB 定义“生意怎么发生”。
Skills / CLI 定义“动作怎么执行”。
JovaAI OS 定义“谁可以在什么边界内执行”。
JovaClaw 定义“智能体如何真正调用并完成动作”。

<!-- P00992; style=Normal -->
例如报价：

<!-- P00993; style=Normal -->
ICB 知道报价涉及客户、商品、价格、合同、账期、库存、毛利、审批。
Skills 负责查客户、查商品、查库存、算价格、生成报价单、发邮件、创建任务、触发审批。
OS 负责权限、身份、上下文、日志和协同。
JovaClaw 负责把报价智能体的决策变成真实业务动作。

<!-- P00994; style=Normal -->
这才是一套完整能力。

<!-- P00995; style=Normal -->
很多公司可以接 API，但接 API 不等于懂交易。
很多公司可以做工具调用，但工具调用不等于产业执行。
很多公司可以做 Agent，但 Agent 不等于业务闭环。

<!-- P00996; style=Normal -->
JovaAI 的壁垒，在于 ICB、Skills / CLI、OS、JovaClaw 是一体的。

<!-- P00997; style=Normal -->
### 6.6 ICB 的对外表达方式

<!-- P00998; style=Normal -->
ICB 对外表达要避免太技术化，也不能讲成“我们有一堆工具”。

<!-- P00999; style=Normal -->
对客户高层，可以这样讲：

<!-- P01000; style=Normal -->
JovaAI ICB 是把企业多年沉淀在老板、老业务员、老采购、Excel、ERP、微信和历史订单里的交易经验，拆成 AI 能理解、能执行、能复用的产业交易语法。它让智能体不只是回答问题，而是能够在企业真实价格、账期、客户、供应商、合同、订单和履约规则下参与经营。

<!-- P01001; style=Normal -->
对投资人，可以这样讲：

<!-- P01002; style=Normal -->
ICB 是艾氪智能最核心的非模型壁垒。大模型公司解决通用智能，JovaAI ICB 解决产业交易语义。它来自多年真实交易场景沉淀，不是短期靠算法、提示词或 API 接入就能补齐。

<!-- P01003; style=Normal -->
对销售团队，可以这样讲：

<!-- P01004; style=Normal -->
客户懂自己的行业，我们帮客户把行业生意经验变成可执行的 AI 系统。我们不是来替代客户经验，而是把客户经验结构化、工具化、智能体化、可复制化。

<!-- P01005; style=Normal -->
对产品和研发团队，可以这样讲：

<!-- P01006; style=Normal -->
所有场景都要沉淀进 ICB。每做一个客户、一个 POC、一个行业方案，都不能只交付页面和功能，而要反向沉淀交易对象、交易动作、规则、权限、工具、数据结构和智能体链路。
