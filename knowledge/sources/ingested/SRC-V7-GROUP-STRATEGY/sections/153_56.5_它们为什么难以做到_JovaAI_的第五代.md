# 56.5 它们为什么难以做到 JovaAI 的第五代

> 来源：01_艾氪智能集团战略手册 V7.0.docx；定位：P03536–P03551。

<!-- P03536; style=Normal -->
### 56.4 传统软件 CLI 化，是入口迁移后的断臂求生

<!-- P03537; style=Normal -->
AI Agent 时代，软件入口正在迁移。

<!-- P03538; style=Normal -->
过去，软件公司最重要的是 UI 入口。员工每天登录系统，点击菜单，填写表单，提交审批，查看报表。谁拥有 UI，谁就拥有入口、数据和用户习惯。

<!-- P03539; style=Normal -->
但未来，智能体不一定通过 UI 操作系统。智能体需要的是 API、CLI、Skill、MCP、数据库工具和业务工具。它不关心你的界面漂亮不漂亮，而关心能不能被调用、能不能授权、能不能审计、能不能执行业务动作。

<!-- P03540; style=Normal -->
所以，很多传统软件公司开始把自己 API 化、CLI 化、MCP 化、Skill 化，让自己的能力能够被智能体调用。

<!-- P03541; style=Normal -->
这当然是必要动作，但本质上也是入口迁移后的断臂求生。

<!-- P03542; style=Normal -->
因为当 UI 不再是主入口，传统软件必须接受一个现实：它越来越可能从“人类每天打开的入口”，退化为“智能体调用的工具节点”。

<!-- P03543; style=Normal -->
这不是说传统软件没有价值。相反，它的数据、流程和系统能力仍然很重要。但它的入口地位正在变化。

<!-- P03544; style=Normal -->
传统软件如果只做 CLI 化，仍然只是工具节点。JovaAI 要做的是组织这些工具节点、智能体、企业和交易规则共同运行的 OS。

<!-- P03545; style=Normal -->
### 56.5 它们为什么难以做到 JovaAI 的第五代

<!-- P03546; style=Normal -->
ERP / SaaS / CRM / ITSM 公司难以直接做到 JovaAI 的第五代，有几个原因。

<!-- P03547; style=Normal -->
第一，它们主要围绕企业内部系统设计。
即使连接外部供应商和客户，也往往仍然是以单企业为中心，而不是让每个企业既独立又互联。

<!-- P03548; style=Normal -->
第二，它们的核心是软件模块，不是产业交易语言。
ERP 有订单、库存、财务模块，CRM 有客户、商机、服务模块，但这不等于 ICB 产业交易语言。ICB 要承载商品、价格、账期、货权、服务、履约、开票、结算、渠道、关务、合同和多主体交易关系。

<!-- P03549; style=Normal -->
第三，它们的 AI 多数嵌入旧流程。
AI 被加到原有模块里，提升查询、生成和流程效率，但不一定重构 AI 原生商业模式。

<!-- P03550; style=Normal -->
第四，它们不天然具备 JovaAI 独立站网络逻辑。
JovaAI 不是让所有企业住进一个中心化系统，而是让每个企业拥有 AI 原生主权节点，同时通过 OS 协同。

<!-- P03551; style=Normal -->
第五，它们不天然围绕九大 AI 商业模式设计。
传统软件主要按模块卖，JovaAI 要按商业模式升级路径帮助客户从场景走向网络。
