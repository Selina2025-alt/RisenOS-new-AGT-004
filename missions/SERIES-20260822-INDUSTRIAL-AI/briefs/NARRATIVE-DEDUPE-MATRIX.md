## 3. 高风险重复与处理方式

### 01 与 02

- 重复风险：两篇都容易写成“实体产业复杂，所以艾氪智能做产业 AI”。
- 处理：01 只证明问题复杂；02 才回答为什么艾氪智能选择这一方向及如何定义价值。

### 01 与 03

- 重复风险：01 解释落地障碍时提前讲完 Agentic OS。
- 处理：01 只提出“需要系统条件”；03 才逐项解释这些系统条件和产品对应关系。

### 02 与 03

- 重复风险：两篇都堆叠公司数据、产品线和架构。
- 处理：02 的企业知识用于证明战略与产业积累；03 的企业知识用于解释系统结构。相同事实若必须出现，第二次只作简短引用。

### 03 与 04

- 重复风险：角色、权限和协作同时属于系统与组织。
- 处理：03 讲“系统必须支持什么”；04 讲“这些能力如何改变人和组织关系”。

### 04 与 05

- 重复风险：第四篇结尾直接写成企业行动清单。
- 处理：04 只提出管理问题；05 才给出优先级、前置条件、验证方式和停止条件。

## 5. 跨篇一致性控制

五篇共用一份术语和 Claim 主表，但每篇保存独立快照。以下内容必须一致：

- 企业、产品、架构和智能体正式名称；
- 产业级 Agentic OS 的定义；
- AI工具、Agent、智能体团队和系统能力的关系；
- 人工最终决定权和责任边界；
- 已公开数据的数值、时间和统计口径；
- 产品状态、适用范围和禁止表达。

以下内容允许因文章任务不同而变化：

- 切入事件和外部来源；
- 受众的专业深度；
- 企业融合位置；
- 解释案例；
- CTA和行动问题。

## 6. 系列级验收清单

- [ ] 任意两篇不存在连续两段以上的同义复述；
- [ ] 相同公司事实第二次出现时有新的论证用途；
- [ ] 五篇标题分别对应问题、选择、系统、组织和行动；
- [ ] 每篇只有一个首要结论；
- [ ] 每篇至少回应一个读者异议；
- [ ] 任何跨篇引用均能追溯到同一有效 Claim；
- [ ] 任何产品出现均通过“删除测试”和相关性检查；
- [ ] 没有为形成系列而强行让五篇都提Nomos、ICB或同一个案例；
- [ ] 第五篇形成新行动价值，而不是前四篇摘要拼接。
